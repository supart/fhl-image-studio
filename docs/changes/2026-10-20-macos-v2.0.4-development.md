## macOS 平台修复

- 原生文件拖拽把 AppKit 操作保持在最小 Objective-C 边界内：当前已在主线程时直接开始拖拽，只有后台线程才同步切换到主队列，避免 `dispatch_sync` 主线程自锁。
- 拖拽前在 Go 与 AppKit 两侧校验空路径、绝对路径、符号链接、文件存在性、常规文件类型和 file URL；Wails 方法、事件名与前端数据流保持不变。
- 目录包含、删除边界和预览路径统一复用安全路径解析：解析现有祖先并保留未创建的后缀，识别 macOS `/var` 与 `/private/var` 的同一路径；悬空符号链接或逃逸路径按失败关闭处理。
- Darwin 默认输出根对应的日志目录恢复为 `~/Library/Logs/FHL Studio`；自定义输出根或 portable 输出继续使用 `<root>/log`。其他平台行为不变。
- CLI 环境配置的输入、输出和原始日志目录使用宿主 `filepath.Separator`；macOS 生成 `./...`，Windows 继续生成 `.\\...`。
- Darwin CGO、Core Image、AppKit 和主程序链接最低版本统一为 macOS 13.0。

## Windows V2.0.4 功能与 V2.0.3 视觉恢复

- 根因是 V2.0.4 前端丢失了 V2.0.3 的宿主/展示平台分离：真实 macOS 宿主被直接送入 Apple/Liquid Glass 分支，Windows 已有的一键配置、传输模式、完整历史、状态栏和 Footer 因显式平台判断而没有挂载，布局也切换为更宽侧栏与更大间距。
- 平台状态恢复为 `hostPlatform=macos`、`presentationPlatform=windows`、`desktopUIVariant=windows-parity`，并公开 `isMacHost`、`isWindowsHost`、`usesMacDesktopUI`、`usesWindowsDesktopUI`。展示结构使用 presentation 状态；Finder、Keychain、WKWebView、原生拖拽/面板、路径、快捷键和窗口能力使用 host 状态。
- 根节点写入 `data-platform="macos"`、`data-presentation-platform="windows"`、`data-desktop-ui-variant="windows-parity"` 和 `data-ui-family="fluent"`；macOS 开发与打包入口显式设置 `VITE_DESKTOP_UI_VARIANT=windows-parity`，但继续保持 `VITE_TARGET_PLATFORM=macos`。
- Fluent theme、controls、compose、history、flyouts 与 responsive 样式改由 `data-presentation-platform="windows"` 驱动。视觉基线锁定为 V2.0.3：浅色 `#f3f3f3/#fbfbfb/#ffffff/#005fb8`，深色 `#202020/#2b2b2b/#333333/#60cdff`，左/右栏 `360px/320px`、Header `48px`、workspace bar `38px`、卡片/控件圆角 `8px/4px`，macOS Header 保留 `86px` 交通灯安全区。
- Header 恢复一键/完整 FHL 配置、FHL Images/Responses 切换、推广信息、QQ群/注册链接、一言、GitHub、Star 和主题入口；完整配置弹窗继续复用文本 API、10 个 Images API 槽、批量粘贴、并发和高级上游配置。
- 左栏复用 Windows 紧凑 Compose/Advanced 与文生图/图生图模式；中央区域复用单排工具栏和完整空闲/运行/结果状态；右栏复用 `WindowsHistoryRail` 的模式计数、搜索、日期筛选、批次队列、最近作品、素材管理、结果列表、提示词分组和完整相册；Footer 恢复输出目录、GitHub、反馈、统计、运行状态和版本。
- 当前 V2.0.4 的标注、本地编辑、360、API 池、动态模型和批次任务保持在同一工作区内，没有通过回退旧文件实现 parity；Star 弹窗继续沿用既有一次性存储语义。

## 只读产物验证

- `scripts/verify-local-macos-release.mjs` 只验证已有 `.app`，不构建、不签名、不覆盖版本或产物。
- 验证器从 plist 与项目元数据动态取得主程序，校验 bundle 目录、图标、可执行权限、版本、Bundle ID、最低系统版本、应用分类、HiDPI、本地网络设置、两项 UI baseline 元数据，以及 `Contents/Resources/顶部推广信息.txt` 的存在性和大小上限。
- 主程序架构必须严格为 `arm64` 与 `x86_64`；签名必须为 ad-hoc、启用 hardened runtime、标识符正确，并且最终签名 entitlement 仅为要求的 JIT entitlement。
- 验证器执行 `codesign --verify --deep --strict`，并将 `spctl` 结果作为分发信任信息记录，不把 ad-hoc 包的 Gatekeeper 拒绝误判为本机构建失败。
- 签名后计算主 Mach-O SHA-256，并按 POSIX 相对路径字节排序，对目录、文件内容和符号链接目标生成确定性的 bundle 内容清单 SHA-256。
