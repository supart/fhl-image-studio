## 根因复核

- 失败相机图自然尺寸为 `5168×3448`，文件约 `9.08MB`，含约 `44KB` EXIF 元数据；原始 JPEG 直接进入 FHL Images 编辑请求时稳定返回上游 400。
- 同一张图规范化为 `1600×1067`、无 EXIF 的 RGB JPEG 后，使用同一 FHL Images 配置和同一提示词可以成功生成。
- 先前的 `7999 / 8000 / 8192 / 8193px` 合成尺寸边界测试均成功，因此本问题不能简单归因于 8K 像素边界；文件体积、元数据和编码格式也是实际兼容性因素。

## 实现结果

- `image-studio/frontend/dev/browserJobProxy.ts` 仅在官方 FHL、`mode=edit`、`apiMode=images|responses` 时启用预处理。
- 参考图满足任一条件时生成临时 JPEG：最长边超过 `1600px`、文件超过 `6MiB`、存在透明通道。
- 上传副本按比例缩放到最长边 `1600px`，白底合成，质量 `88`，不保留 EXIF；源图自然尺寸和像素内容不被覆盖。
- 预检无法解码、读取尺寸、编码或写入临时文件时，在 CLI 启动前直接失败并清理已生成副本，不留下半成品任务。
- CLI 子进程关闭、启动错误、取消和掩码写入失败路径都会清理临时副本；任务状态显示原图尺寸、文件大小和副本尺寸。
- 已确认安全的 JPEG（不超过 `1600px`、不超过 `6MiB`、无透明通道）原样传递；APIMart、RunningHub、非编辑模式和无参考图请求不进入该逻辑。

## Codex 浏览器真实验收

- 本地页面：`http://127.0.0.1:5173/`，使用现有 FHL Images 配置，单任务、单参考图。
