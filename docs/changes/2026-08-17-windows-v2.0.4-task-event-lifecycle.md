# Windows V2.0.4 任务事件生命周期

## 目标与边界

迁移浏览器 workspace SSE、Android 单任务订阅和原生 Wails 六类任务事件的订阅所有权，保持 `useStudioStore`、任务记录、历史结构、Bridge v1、序列化和传输入口不变。本批不拆 `host.ts`，不修改请求合约、Photoshop Bridge、CI 或发布链。

## 审计发现与修复

- 新增 `studioStore.browserTaskLifecycle.ts`，统一持有 browser workspace、Android job 订阅、refresh 单飞、待同步 job 集合和 reset generation；重复 sync 不再重复订阅，error/close 双回调只触发一次协调。
- 浏览器模式每个活动工作区只保留一条 SSE，Android 模式按 job 订阅；事件同时校验 group workspace、slot workspace 和 job ID，未知或已关闭工作区的迟到事件直接忽略。
- 同一工作区多个 job 的提前断流会合并到同一 refresh pass；pass 运行期间新增 job 会进入下一 pass，不丢成功历史同步请求。
- 关闭工作区时同步删除其 `jobGroupsByWorkspace` 缓存、解绑原生 job 生命周期并重算浏览器订阅，修复迟到 SSE 复活已关闭任务组和 `runningJobMeta` 的问题。
- 扩展 `desktopJobEvents.ts` 为原生生命周期注册表，统一注册 progress/log/preview/result/error/settled 六类 handler；事件序号、首个终态、重复终态、幂等解绑和 reset 全量清理由注册表负责。
- `settled` 不受旧序号阻断，始终释放保留的 `runningJobMeta` 并解绑六类 handler；reset 后即使测试直接调用已捕获的迟到 callback，也不会产生副作用。
- 浏览器历史同步和原生结果后处理增加 reset epoch、工作区存在性及任务存在性门禁；全景自动贴回在每个异步边界重新检查当前性，避免关闭工作区或初始化后的旧异步结果继续写 Store 或弹 Toast。
- 专业 agent 只读复核确认了关闭工作区迟到 SSE、原生 handler 无全局注册表、异步结果缺少 workspace 门禁，以及旧 refresh 合并丢失第二个 job ID 四类风险；均在本批边界内处理。

## 行为覆盖

- 浏览器生命周期 5 条测试覆盖 browser/Android 两种订阅模式、重复 sync、终态解绑、跨工作区/跨 job 隔离、error+close 去重、同工作区多 job refresh 和 reset 防复活。
- 原生生命周期测试覆盖旧事件兼容、重复/乱序拒绝、单一 result/error 终态、低序号 settled、六 handler 一次解绑、全量 reset 和迟到 settled 无副作用。
- 真实 Store 回归覆盖原生 result 只提交一次、settled 释放元数据、应用初始化解绑已取消原生生命周期，以及关闭工作区同步清理任务组和订阅。
- 删除旧的 browser Map、Wails `EventsOn` 位置等源码字符串断言；保留与用户数据/历史 API 来源直接相关的兼容断言。
