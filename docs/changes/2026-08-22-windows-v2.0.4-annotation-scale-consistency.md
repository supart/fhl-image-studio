# Windows V2.0.4 标注尺寸与画布缩放统一

## 根因

旧标注对象已经按图像坐标保存，但渲染和 PNG 合成又按 `viewScale` 二次缩小线宽、字体和箭头尺寸。画布缩放后，视窗看到的粗细与最终 Output 不一致；同时标注描边复用了蒙版 `brushSize`，无法独立控制。

## 实现

- `Annotation` 新增可选 `fontSize`；旧数据缺失时使用 `20px`，旧 `strokeWidth` 继续按图像像素解释。正常进入标注时，字体按当前 4K 临时源最长边自动初始化。
- 新增工作区隔离的 `annotationStrokeWidth`（`1–96px`，默认 `4px`）和 `annotationFontSize`（`8–128px`）；无有效自然尺寸时才回退 `20px`，蒙版 `brushSize` 保持原语义。
- 标注工具栏增加“标注描边”“标注字体”两个独立滑条和固定“等比锁定”状态。选中对象时立即写回对象并进入标注撤销栈，没有选中对象时只更新新建标注默认值。
- `AnnotationShape`、`AnnotationLayer`、文字编辑器和 `annotationComposite` 统一直接使用图像像素线宽、字体和箭头头部尺寸；`viewScale` 只负责 Stage 整体缩放，命中测试容差仍按屏幕交互需要换算。
- 合成流程不再读取 `canvasView.scale`，继续复用 4K 临时源、Output、历史和参考图事务，不调用真实生图 API，也不改变 Android 产品行为。

## 未验证风险与回退

- 浏览器驱动对受控 `input[type=range]` 的 `fill` 会改变原生值但不总是触发 React 文案重绘；自动化已验证控件存在、范围和可访问名称，真实鼠标拖动仍需在 Windows Wails 宿主和不同 DPI 下复核。
- 真实 Wails DPI/EXIF 方向、字体抗锯齿和超大图桌面合成仍沿用 4K/100MP 门禁批次的观察项。
- 当前工作树未提交、未设置 upstream、未推送；回退只使用后续明确提交的 `git revert`，不修改 Android、V2.0.3、Cowart 源码、用户图片或 API 凭据。
