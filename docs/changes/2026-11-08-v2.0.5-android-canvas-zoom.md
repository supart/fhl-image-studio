# V2.0.5 Android CanvasStage 缩放回弹修复

日期：2026-11-08

## 根因

工具栏缩放、双击、滚轮、触摸 pinch 和 Konva 拖拽结束回调可能交错执行。旧实现从闭包中的 `view` 读取状态，延迟 `dragend` 会把旧比例写回，表现为缩小后自动回到此前的放大状态。

## 修复

- 使用 `viewRef` 同步保存最新的 `{ scale, x, y }`，所有缩放和坐标换算都读取它。
- 双指开始时停止 Konva 拖拽；pinch 结束后一次性忽略延迟 `dragend`，避免拖拽回调覆盖 pinch 的比例。
- `onDragEnd` 只合并最新视图的 `x/y`，保留当前 `scale`；切图、旋转、翻转和重置时同步清理视图及抑制状态。
- 保留缩放边界 `0.05..8` 与现有 Android 控制按钮行为。

## 验证范围

- 静态聚焦测试覆盖 `viewRef`、pinch `stopDrag`、延迟 `dragend` 防护和最新比例合并，并拒绝旧的 `setView({ ...view, ... })` 写法。
- 长构建与 2K 模拟器的连续放大、缩小、双指缩放、拖拽和重置回归在后续批次执行。

构建备注：中文工作区路径下 Gradle JUnit worker 可能出现既知的类加载失败；这属于路径环境问题，重跑时使用临时 ASCII 映射，不改变源码或测试结论。

## 后续验证结果

- 工具栏连续缩放 `26% → 31% → 26%` 后未回弹；在 `31%` 状态拖拽后 fresh screen 仍为 `31%`，随后重置视图并完成 fresh-read。
- 双击与双指 pinch 已通过 Android MCP 执行，但无截图的 accessibility 状态没有独立暴露比例变化，因此仅记录为尝试，不标记为手势通过。
