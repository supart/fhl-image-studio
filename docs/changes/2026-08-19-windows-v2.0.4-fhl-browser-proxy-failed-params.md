# Windows V2.0.4 FHL 浏览器代理大图保护与失败任务参数菜单

## 批次目标

- 修复 Codex 浏览器批量图生图绕过前端 remote-kernel、直接把超大参考图交给本地 CLI 的路径。
- 对官方 FHL Images / Responses 图生图在 CLI 启动前执行真实像素尺寸预检，超过安全长边时生成临时上传副本。
- 失败任务卡片支持右键打开共享历史菜单，并执行“应用参数（不生成）”，不自动重新提交。
- 只修改 Windows V2.0.4；不修改 Android、APIMart、RunningHub、V2.0.3、正式附件或远程 GitHub。

## 根因

浏览器任务实际路径是 `browserJobClient.ts -> Vite dev/browserJobProxy.ts -> runtime/cli/gptcodex-image.exe`。此前只在 `remote-kernel/common.ts` 中保护上传尺寸，浏览器批量任务没有经过该逻辑，因此上游可能收到超过限制的原始参考图并返回 `Invalid image file or mode for image 1`。

## 实现结果

- `frontend/dev/browserJobProxy.ts` 仅对官方 FHL、`mode=edit`、`apiMode=images|responses` 生效。
- 每张参考图使用 `sharp.metadata()` 读取自然像素尺寸；长边超过 `8192px` 时按比例缩放为白底 JPEG，质量 `82`，再把临时路径传给 CLI。
- 9000×6000 参考图在真实浏览器任务中生成了 8192×5461 上传副本；原图和受管媒体仍保持原始尺寸。
- 自动缩放阶段会在任务状态中记录原始长边和副本长边；临时副本在 CLI `close/error` 或取消路径清理，任务成功后 `output/log` 中无残留 `*fhl-source*` 文件。
- 读取、解码、编码或掩码写入失败会在启动子进程前将任务标记为失败，不留下运行中假任务；取消不会创建半成品。
- `BatchResultGrid` 失败卡片增加右键入口，`CanvasStage` 为失败任务构造完整 `HistoryItem` 上下文；共享菜单的“应用参数（不生成）”只回写编辑参数，不调用 `submit()`。
- APIMart、RunningHub、Android、提示词优化、反推图像和非编辑模式保持原行为。

## 真实浏览器验收

本地页面：`http://127.0.0.1:5173/`，使用 Codex 浏览器已有 FHL Images 配置。

1. 失败任务卡片右键打开菜单，确认出现“应用参数（不生成）”；点击后菜单关闭、提示词和参考图恢复，未创建新任务。
2. 导入临时 9000×6000 JPEG，提交单张 FHL Images 图生图。浏览器任务最终显示成功，输出文件为 `20260819-010323-590-将这段室内楼梯整体改.webp`。
3. 代理临时文件实测尺寸为 `8192×5461`、JPEG、RGB、可解码；任务结束后临时文件已清理。
4. 页面控制台 warning/error 为 `0`；未执行批量重试，未修改原图历史尺寸。

此前同源尺寸边界的顺序测试 `7999 / 8000 / 8192 / 8193px` 均成功，因此本批继续采用已确认的保守上限 `8192px`，不把问题简单归因于 8K 边界。
