# Windows V2.0.4 GitHub 正式发布

## 发布范围

- 发布目标为 Windows 10/11 x64 Portable `V2.0.4`。
- GitHub 使用独立分支 `release/windows-v2.0.4` 和标签 `windows-v2.0.4-release`。
- 不合并或修改远程 `main`，不替代 macOS `v2.0.3`、`v2.0.3.1`、Android 或 V2.0.3 Windows 发布。
- Photoshop UXP 插件为独立项目，不进入仓库、源码 ZIP 或 Release 附件。

## 发布资产

- `FHL-Image-Studio-Desktop-V2.0.4-Windows-Portable.zip`：从最终标签提交重建的 Windows 免安装包。
- `FHL-Image-Studio-Desktop-V2.0.4-Windows-Source.zip`：与标签对应的脱敏源码归档。
- `SHA256SUMS.txt`：两个 ZIP 的 SHA-256 校验值。

## 人工验收

- Windows V2.0.4 整体人工验收已由用户确认通过。
- Images API 多参考图修复已使用三张参考图在完整 Wails 程序中通过真实 FHL Images 上游验证。
- 局部重绘往返、多次生成后的贴回状态、文本模型选择和 Photoshop Bridge 对接已在开发候选中完成验收。

## 脱敏与默认状态

- 发布源码和 Portable 不含 API Key、Token、Credential Manager 数据、`cli.env.local`、WebView、用户图片、历史、任务或日志。
- 新电脑或新 Windows 账户以无 API、无活动 Profile 状态启动，文本模型默认 `gpt-5.6-sol`。
- 同一 Windows 账户可能读取 Credential Manager 中已有凭据，此行为在发布说明中单独标明。

## 验证与回滚

- 本地门禁、GitHub CI、源码合规扫描、Portable 安全扫描、独立解压校验和 Bridge health/session/profile 握手必须全部通过。
- 首次远端 CI 在 Windows 临时目录的 8.3 短路径与长路径比较上暴露误判；发布分支统一在 `isWithinRoot()` 中规范化两边路径后继续执行原有相对路径边界判断，避免合法托管图片被拒绝且不放宽越界访问。
- Release 先以草稿状态上传并回读校验附件，然后公开为正式稳定版。
- 任一门禁失败时停止公开，不强推、不移动正式标签、不修改 macOS 或 Android 发布。
