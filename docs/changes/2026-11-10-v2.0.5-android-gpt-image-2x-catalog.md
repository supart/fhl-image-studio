## 范围

- 仅修改 Android V2.0.5 工作区；V2.0.4、Windows 参考实现、历史归档和远端保持不变。
- 保留 Images/Responses、FHL1-FHL10、Keystore、4/40 调度、后台恢复、图生图、多图重复 `image` 和真实 Alpha 校验。
- 不读取凭据，不执行付费生图，不生成正式签名包。

## 动态目录

- 目录缓存升级为 v2；旧 v1 不能继续证明模型有效，旧 Profile 模型 ID 只作为迁移证据保留。
- 前端和 Android 原生统一使用 `^gpt-image-2(?:\.(\d+))?(?:-[a-z0-9][a-z0-9._-]*)?$`，保留 provider 精确 ID，并支持未来 GPT Image 2.x minor/后缀。
- 空值、Unicode 控制字符、超过 128 个码点、非法 family、文本/Embedding/音频/语音/审核/重排/转录/TTS/Whisper 和仅图像输入模型被过滤或失败关闭。
- 大小写不敏感重复项按能力 AND 合并；provider 显式 `false` 和 `available=false` 优先于默认能力。
- 裸 `gpt-image-2.5` 固定为不可调用模糊别名；非 GPT Image 2.x 图像候选只作诊断，不能提交。

## 十槽与原生证明

- 每个有 Keystore 凭据且启用的槽独立请求目录；UI 展示安全并集，只有所有目标槽都存在且允许生成的模型可选。
- 缺少模型的槽显示安全 FHL 槽号；generation/edit/transparency 能力按全部目标槽保守合并。
- 原生为每个目录响应生成绑定 Profile、槽号、Base URL、provider、时间和能力的 receipt；统一保存时生成批次 validation ID。
- Profile、请求、任务组/槽、历史和三条冻结重放路径携带可用性、三项能力和 validation ID。凭据或配置改变会撤销证明。
- 原生提交校验 exact model、目录身份、时间、Profile/槽和能力；缺字段、字符串布尔值、伪造证明或能力放大全部失败关闭。重复提交先返回已持久化组，避免 Profile 后续变化破坏幂等。

## 透明与 UI

- 透明要求精确 GPT Image 2.x、minor `>=5`、非裸 2.5、provider 允许透明、有效证明、路由允许且输出 PNG；否则回退普通背景并给出原因。
- 统一模型卡片保持常规 `190px`、窄屏 `236px`；模型列表独立滚动，禁用项可聚焦但不可选择，完整 ID 和中文原因可见。
- 刷新失败保留上次成功列表和当前模型但禁止保存；成功刷新不会自动选择第一个模型，也不会自动提交。
