# Windows V2.0.4 工作区、历史与素材模块化

## 目标与边界

只迁移工作区、历史分页/预览水合、素材组及相关动作，保持 `useStudioStore` 公共入口、存储 namespace、V2.0.3 迁移标记、API/Profile/凭据、序列化结构和宿主接口不变。本批不迁移任务队列、任务生命周期或 `host.ts`，不调用真实 API，不生成发布包。

## 实现

- `studioStore.workspaces.ts` 统一复用工作区选择补丁，新建、切换和关闭活动工作区不再维护三份重复字段映射。
- 工作区模块不再直接绑定 Wails：取消任务、事件解绑和活动工作区快照通过显式运行时依赖注入，`historyItemsByIds` 迁入纯 `workspaceRuntime.ts`。
- 新增 `studioStore.materials.ts`，承接素材管理器开关、素材组增删改、历史引用移动、参考图组应用及 output 同步；主 Store 保留同名兼容转发。
- 历史分页、单次并发控制和预览水合迁入 `studioStore.media.ts`；初始化继续复用同一预览水合入口，应用初始化通过 pending history handle 等待在途分页。
- 分页响应改为与 await 后的实时历史合并，避免等待期间新增结果被旧快照覆盖；排序方向变化后拒绝旧方向响应并自动为当前方向重新加载。
- 历史分页继续受应用 reset epoch 隔离，初始化开始后不会写回旧历史或预览。
- 修复 `loadMaterialGroups()` 的既有语义错误：未提供历史过滤条件时完整保留持久化引用，只有显式提供历史集合时才剪枝，避免启动后素材引用丢失。
- 状态层 README 补充工作区、媒体和素材模块职责。

专业 agent 只读审计还确认 `editAutoAspectUserLocked` 同时存在顶层与工作区两份状态来源。本批为保持模块化行为等价，没有顺手改写该字段；应在后续独立批次先建立双向同步测试，再收敛所有权。
