# Windows V2.0.4 自动尺寸锁状态所有权

## 目标与边界

只修复图生图自动比例的手动尺寸锁在顶层 Store 与 Workspace 之间漂移的问题，并明确状态所有权。本批不迁移任务队列、不拆 `host.ts`、不修改 Bridge、API、namespace、迁移标记或序列化格式。

## 根因

- 用户手动修改尺寸时，`setField("size")` 只将活动 Workspace 标记为已锁定，而提交流程读取顶层旧字段，可能再次自动计算并覆盖手动尺寸。
- Panorama 会同时写入顶层和 Workspace；工作区切换原先没有恢复目标 Workspace 的锁镜像，未锁工作区可能继承上一标签的锁状态。
- 自动比例解锁主要更新 Workspace；bootstrap 恢复活动 Workspace 时也没有恢复顶层镜像。

## 实现

- 以 `Workspace.editAutoAspectUserLocked` 为唯一业务权威，顶层字段只作为当前活动工作区的兼容镜像。
- 新增 `activeWorkspaceEditAutoAspectUserLocked()`，提交判断直接读取活动 Workspace；仅在找不到活动 Workspace 时回退顶层兼容值。
- `setSharedEditAutoAspectLock()` 同步 Workspace 和活动镜像，异步自动比例重算与重置路径也同步镜像。
- `workspaceSelectionPatch()` 和 bootstrap 恢复显式写入目标 Workspace 的锁状态，切换与重载不再串台。
- 手动尺寸修改把尺寸、Workspace 锁和活动镜像合并为一次原子 Store patch，避免订阅者观察到中间状态。
- 持久化结构和字段名称不变，旧会话继续由现有规范化入口读取。

## 行为测试

- 扩展真实 `useStudioStore` 工作区测试：在自动比例编辑模式手动修改尺寸后，Workspace 与活动镜像同时锁定。
- 故意把顶层镜像改回旧值，确认活动 Workspace 权威读取仍返回锁定。
- 切换到默认未锁工作区后镜像为未锁，再切回原工作区后恢复锁定。
- 更新提交与 bootstrap 的守卫，确保提交使用权威读取且恢复路径继续同步镜像。
