# Windows V2.0.4 卷帘对比使用原始参考图

## 批次范围

- 分支：`codex/windows-v2.0.4-feature/local-edit-360-parity`
- 仅修改 Windows V2.0.4 前端对比来源和相关合同测试；Android、V2.0.3、正式附件、API 配置和远程 GitHub 未修改。
- 本批不调用真实或付费生图 API，不创建任务，不删除历史或源文件。

## 问题与根因

卷帘对比左侧原图被拉伸后明显模糊。浏览器实测左侧 `<img>` 使用 `/media/thumb/...`，自然尺寸为 `384×216`，而右侧成图使用 `/media/full/...`，自然尺寸为 `2048×1152`。

根因在临时参考图物化：参考图已有 `previewUrl` 时，旧逻辑跳过 `RegisterImportedImageAsset()`，并把缩略图直接写入 `fullUrl`。`CanvasStage` 随后把这个地址直接交给卷帘组件，导致缩略图填满大画布。

## 实现结果

- 参考图物化现在按受管路径尝试注册完整媒体，即使缩略图已经存在；外部路径在注册失败后先导入受管路径再重试。
- `fullUrl` 只接受真实完整媒体地址，不再把 `/media/thumb/` 或 `/media/preview/` 作为完整图写入。
- 完整媒体不可用时保留原有 Blob/Base64 优先和缩略图最后降级，不阻断对比功能。
- Windows 双图和卷帘对比都通过 `historyFullSrc()` 解析左右地址；该 helper 额外拒绝被误存的缩略图 `fullUrl`，并继续支持 `imageId` 推导完整媒体。
- 不把完整图片 Base64 写入 workspace 或历史；原图文件和现有缩略图不覆盖。
