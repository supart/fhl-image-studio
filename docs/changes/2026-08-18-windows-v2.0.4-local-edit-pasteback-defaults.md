# Windows V2.0.4 局部贴回像素边界与 2K 默认修复

## 批次目标

修复普通图局部编辑自动贴回时，超分辨率编辑结果被按输出像素尺寸放大、覆盖超出原镜头框的问题；同时确保旧工作区缺少分辨率字段和“一键初始化”都恢复到统一的 2K 默认值。

本批只修改 Windows V2.0.4 源码，不修改 Android、V2.0.3、正式附件、正式标签或远程 GitHub。

## 360 源码对照结论

已读取 `image-studio/frontend/src/panorama/core.ts` 的 `mapPanoramaPastebackSample` 与 `pastePanoramaRoundtripBase64`：

- 360 贴回把原始镜头矩形（`roundtripState.rect`）作为物理范围。
- 编辑结果实际尺寸只用于双线性采样坐标，不会因为输出图是 2K、4K 或其他尺寸而扩大贴回范围。
- 手动对齐时才应用平移、缩放、旋转；未提供对齐参数时使用原镜头范围和默认球面投影。

普通图原实现把 `editedWidth / expectedWidth`、`editedHeight / expectedHeight` 乘进物理宽高，和 360 规则不一致。这是超分辨率结果自动贴回越界的根因。

## 修改内容

### 普通图自动贴回

- `mapPlanarPastebackSample` 现在始终以 `cropRect.width/height` 定义物理贴回范围。
- 编辑图尺寸仅影响采样坐标，任意分辨率结果都会被重采样到原镜头框内。
- `composePlanarRoundtripPixels` 的工作循环按裁切框大小估算；只有明确的对齐缩放或位移才会扩大/移动覆盖区域。
- 裁切框外像素保持原图内容，现有旋转、颜色调整、羽化和蒙版路径不变。

### 默认分辨率

- 工作区恢复时缺少或为空的 `size` 字段改为回退到 `DEFAULT_FHL_SIZE`（`2048x2048`）。
- `createDefaultWorkspace` 原有 2K 默认保持不变；一键初始化通过同一默认工作区路径恢复 2K。
- 历史结果和显式保存的旧尺寸不改写，`1024x1024` 只作为旧记录或协议兼容值保留。
