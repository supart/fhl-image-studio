## 透明 PNG 黑底显示修复

- 定位结果：透明 PNG 的正式返回和保存文件均有真实 Alpha；问题发生在 Android 原生预览，旧实现将透明 Bitmap 一律压成 JPEG，前端优先加载该预览后透明区表现为黑底。
- 新增 `AndroidImagePreview.kt` 统一编码与 MIME：有 Alpha 时输出 PNG，无 Alpha 时保留 JPEG；接入后台任务预览、picker/import、`RegisterImportedImageAsset` 和 `RegisterMediaAsset`。
- 旧 `.png` 正式文件配 `.jpg/.jpeg` 缩略图时，注册媒体改读正式 PNG 生成正确 data URL，使本地旧历史在恢复时自愈；正式文件、相册文件和历史证据均不改写。
- 新增透明/不透明 fixture：校验预览扩展名、MIME、PNG 像素 Alpha、后台 `createPreviewFile` 和旧 JPEG thumb 选择契约。
- 六个 Android PowerShell 验证脚本使用同一 `Get-Sha256Hex`：`Get-FileHash` 存在时沿用，不存在时使用 .NET `System.Security.Cryptography.SHA256` 流式计算；不跳过哈希验证。

## FHL 十槽统一模型配置修复（实现中）

- 根因：既有统一选择只同步十槽 `imageModelID`，只有发起目录请求的当前槽获得验证时间、目录 Base URL 和 provider；调度命中其他槽时，严格目录门禁按设计拒绝提交并显示“尚未通过目录验证”。
- 新行为：FHL API 10 槽提供唯一统一模型入口，逐一使用每个“已配置且启用”槽位自己的 Keystore Key 请求 `/v1/models`，对可用精确模型取保守交集；空槽和停用槽不参与本次验证。
- 提交规则：全部目标槽成功后才写入一次共享目录快照，并通过一次状态提交为目标槽写入同一模型和验证元数据；任何失败都不改变旧目录、模型或验证状态，错误只标识 FHL 槽号和固定脱敏原因。
- UI 边界：FHL 池单槽高级页只读展示统一模型状态，不再允许逐槽拉目录或选模型；APIMart、RunningHub 和独立 FHL Responses 文本模型流程不变。
- 安全边界：Key 只在验证函数局部短暂存在，不进入 UI 状态、持久目录、错误正文、日志或证据；Base URL/provider 不一致时在网络提交前阻断。
- 本节为实现检查点，不代表验证完成。尚待运行聚焦与完整前端测试、TypeScript、`build:android`、Android JVM、`assembleDebug`，并生成新 Debug APK 后通过 `ty-android-mcp` 在 2K 模拟器覆盖安装和验收。
