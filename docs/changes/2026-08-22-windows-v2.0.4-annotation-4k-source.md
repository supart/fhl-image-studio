# Windows V2.0.4 标注工作台 4K 临时源

## 背景

用户反馈 85MP 原图直接进入 Cowart 标注工作台没有实际上传价值，并会在浏览器 Canvas 合成阶段触发约 `768MiB` 工作内存门禁或在 Output 写入阶段失败。本批将标注工作台与原始参考图解耦：工作台只使用运行时压缩副本，原图、历史和原参考图槽保持不变。

## 实现

- 新增 `frontend/src/features/annotation/annotationSource.ts`，把进入标注时的完整媒体解码为自然像素，并将最长边限制为 `3840px`（4K 上限）。保持原图比例；小于 4K 的图不放大。
- `annotationSource` 只存在 Zustand 运行态，不进入 `Workspace` 持久化、Prompt、历史或参考图数据。当前图或 workspace 变化时，旧会话不会被确认流程复用。
- `Toolbar` 进入“图像标注工具”前先等待压缩，显示“压缩中…”并阻止重复点击；压缩失败时停留在原工具状态并提示错误。
- `CanvasStage` 与 `confirmAnnotationComposite()` 复用同一压缩 Blob，确保屏幕坐标、自然像素坐标和最终 PNG 尺寸一致。确认成功后 Output、历史、当前画布和新增参考图都记录压缩后的实际尺寸；原始参考图仍保留。
- 用户最后确认的规则是“超出尺寸按 4K 压缩，不跟随外部 1K/2K 设置”。因此本批不读取外部分辨率选择，也不伪造固定 4K 比例，只使用 4K 最长边上限和原图比例。

## 真实验收

- 测试图：`7876×10835` 楼房 JPG（约 85MP）。进入标注后压缩为 `2791×3840`，比例保持不变。
- 在 Codex 浏览器 `http://127.0.0.1:5173/?preview=mac-workspace` 导入该图、绘制矩形并点击“确认标注”：工具收起，当前画布切换为像素化合成图，Output/历史/参考图槽新增同一成果，输出尺寸为 `2791×3840`，原始参考图保留。
- 本次离线验收未调用真实或付费生图 API；浏览器新增 warning/error 为 `0`。

## 自动化与边界

- `annotationSource.test.mjs` 覆盖小图不放大、85MP 楼房图压缩结果、比例保持和无效尺寸拒绝。
- 收口门禁：`npm run typecheck`、`npm run test:node`（`705/705`）、`npm run test:ui`（`117/117`）、`npm run lint`（`0 errors / 55 existing warnings`）、`npm run build:windows`（`1994 modules`）、`scripts\\dev-check.ps1 -Level Fast`、`scripts\\dev-check.ps1 -Level Batch` 和 `git diff --check` 均通过；Batch 同时通过桌面/CLI Go test/vet、Worker `5/5` 和离线 smoke。
- 保留现有 `100MP / 16,384px / 768MiB` 合成安全门禁；4K 压缩只降低标注工作台输入，不放宽安全检查。
- 不修改 Android、V2.0.3、Cowart 原始源码、用户图片、API 凭据或远程 GitHub。当前工作树未提交、未设置 upstream、未推送；回退只使用后续明确提交的 `git revert`。

## 未验证风险

- 仍需在真实 Windows Wails 宿主和不同 DPI/窗口缩放下观察 `createImageBitmap`、JPEG EXIF 方向以及压缩后文字/形状贴合；浏览器离线路径已覆盖。
- 旧历史若只有 preview 地址且无法读取完整媒体，仍会被本地阻止，不会静默使用缩略图尺寸。
