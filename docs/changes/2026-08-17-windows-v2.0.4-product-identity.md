# Windows V2.0.4 产品身份统一与首轮架构审计

## 目标

将当前开发轨道的活动产品身份统一升级为 `V2.0.4`，以单一清单控制 UI、Wails、Go、CLI、构建与发布链；不发布、不打包正式附件、不修改历史 V2.0.3 说明、稳定数据命名空间或迁移标记。按持续验收要求完成自动化和 Codex 内置浏览器真实点击，并记录后续架构治理顺序。

## 版本实现

- 新增根清单 `product-version.json`，固定：
  - `version=2.0.4`
  - `displayVersion=V2.0.4`
  - `windowsTag=windows-v2.0.4-release`
- 扩展 `scripts/sync-version-metadata.mjs`：
  - `--write` 将清单同步到前端 package、Wails、桌面 Go、CLI 和桌面 E2E。
  - `--check` 只读检查活动版本漂移，作为 CI 和本地构建前门禁。
- 前端品牌与底部版本复用同一个 `appVersion`，不再各自硬编码。
- Windows Portable、源码准备和包内启动器改用稳定文件名；生成产物时才由脚本写入清单版本，后续升级无需复制一套版本化脚本。
- CI 从版本清单取值；Windows Release 只接受清单中的精确标签，并显式拒绝其他 Windows 标签。
- `.gitattributes` 固定 shell 脚本为 LF；`compute-version.sh` 改为内建 `printf`，Windows 工作树中的 Bash 计算通过。
- 桌面媒体与托管路径 Go 测试改用临时 Portable 根，避免测试误写 Windows 稳定用户目录或受限环境下的源码相对回退目录。

## 文档边界

## 浏览器验收发现与修复

初次 `390x844` 验收发现 Windows 桌面网格仍保留 320px 左栏，画布只剩约 70px 并被截断。按本批门禁立即修复并从起点重验：

- `<=980px` 收敛顶部次要促销信息，保留完整品牌、版本、注册链接、API 配置、FHL Images / Responses 模式和设置入口。
- `<=640px` 新增“创作 / 画布 / 历史”分段导航，一次显示一个完整面板；不依赖画布中的滚轮穿透访问历史。
- 窄屏全屏状态排除分段导航和侧栏规则，仍只显示全宽画布。
- 窄屏页脚隐藏非关键统计和外链，只保留输出目录、状态和版本，避免逐字换行。
- `768x1024` 继续使用原有双栏，`1213x930` 继续使用桌面三栏。

真实语义点击路径：

1. 设置 -> 关于 FHL Studio -> 确认 `v2.0.4 · AGPLv3` -> 关闭。
2. 文生图 -> 图生图 -> 文生图，两个按钮的 `aria-pressed` 均按操作更新。
3. 360 工作台 -> 确认空状态和三个本地入口 -> 关闭；未点击生成或导入。
4. `390x844`：创作 -> 画布 -> 历史 -> 画布 -> 全屏 -> 退出全屏 -> 创作。
5. `390x844`：打开设置，确认 348px 对话框完整位于视口内 -> 关闭。
6. `768x1024` 和默认 `1213x930`：复核布局、版本和控制台。

三档视口的 `document/body scrollWidth` 均不超过视口宽度；390px 的三个面板均可由可见分段控件直接访问；浏览器 warning/error 为 `0`。历史图片来自既有开发命名空间，缺失本地文件时只显示既有替代文本；本批没有读取浏览器存储、输出 API Key 或调用上游。

## 独立架构审计

专业 agent 以只读方式完成版本、设置和架构审计，未修改文件、未读取密钥、未调用 API。后续按以下顺序小步治理：

1. `studioStore.ts` 约 8,060 行、约 144 个动作，默认值分散。批次 2 先抽取可行为测试的纯默认工厂和显式 reset policy，不全面重写 Store。
2. 19 个大型组件订阅整个 Zustand Store。只迁移每批触及的组件到精确 selector，并加稳定性测试。
3. `host.ts` 约 1,417 行。保持现有导出不变，后续按文件、媒体、凭据和任务能力拆为内部模块，原文件保留兼容门面。
4. JS 与 Go 请求构造是两份实现。补 Responses、Images、APIMart、RunningHub 共用 golden fixture，再调整实现。
5. Photoshop Bridge 和 CLI 主文件职责过宽。先收窄接口和提取纯逻辑，保持 Bridge v1 与命令兼容。
6. Worker 允许调用方覆盖上游地址；若用于公开部署，会形成任意转发风险。后端加固批次必须确认用途并增加 allowlist、鉴权、速率和请求体限制，不能在本批顺手改协议。
7. 现有大量测试依赖源码正则。新设置初始化测试必须验证实际状态、持久化和零凭据删除调用，不再扩大字符串断言。
