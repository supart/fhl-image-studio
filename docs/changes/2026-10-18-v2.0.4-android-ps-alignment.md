# 2026-10-18 Android V2.0.4 与 PS 外置图像请求对齐

## 初始目标

- 从 `v2.0.3-android` 开始 Android V2.0.4，版本号 `1050004`。
- Android 和 PS 外置 Images API 多参考图请求统一使用重复的 `image` multipart 字段。
- Android FHL 增加 `4:3` 和 `3:4`，保持 APIMart/RunningHub 比例语义独立。
- 完成自动测试、Android 模拟器验证和 PS 外置真实生图验证。

## 证据边界

- Codex 插件 V0.2.2 的重复 `image` 字段修复作为参考实现。
- PS V0.2.0 候选当前源码已包含目标 multipart 行为和 `4:3`/`3:4`，不重复改写生产代码，除非 UXP 实测发现源码与运行包不一致。
- 本记录不得写入 API Key、图片正文或完整真实请求日志。

## 本批实现

- Android remote kernel `requestPayloads.ts` 与原生 `AndroidJobManager.kt` 的 Images API 图生图请求，底图和全部参考图均使用重复的 `image` 字段，`mask` 保持独立字段。
- Android FHL 新增 `4:3`、`3:4` 选项及 1K/2K/4K 尺寸：`1536x1152`、`2048x1536`、`3840x2880`，以及 `1152x1536`、`1536x2048`、`2880x3840`。
- Android 显示名、前端品牌版本、About 页面和构建默认值统一为 `FHL Image Studio 方汤圆版 V2.0.4`、`1050004`。
- 新增 Android instrumentation multipart 检查，验证图片顺序和 `image[]` 缺失。

## 验证结果

- 前端定向测试：`104/104` 通过。
- 前端完整测试：`362/363` 通过；剩余 1 项为既有 `androidAcceptanceAggregator.test.mjs`，Windows PowerShell 子进程无法解析 `Get-FileHash`。切换到 PowerShell 7 后脚本自身的旧 JSON 比较也不兼容，因此未修改验收脚本。
- Android：`npm run build:android`、JVM `testDebugUnitTest`、`:app:assembleDebug`、`:app:connectedDebugAndroidTest` 通过；`Medium_Phone_API_36.1` 上 instrumentation `13/13`。
- 模拟器基础启动、包安装、版本显示、通知权限首启和 logcat 无崩溃通过。证据截图位于忽略目录 `output/v2.0.4-android-emulator/`。
- Photoshop 候选：`npm run debug:all` 全部通过；源码和单测确认多参考图重复 `image` 字段与 4:3/3:4 映射。

## Android 文本模型动态选择

- 扩展现有 `ProbeUpstream` 返回值，浏览器和 Android 原生桥接现在会从 `/v1/models.data` 提取字符串或对象形式的模型 ID，并去空、去重和过滤无效 ID。
- FHL Responses 文本配置新增模型列表和“获取模型”按钮；未保存的新 Key 优先用于探测，否则读取 Android Keystore 中已保存的 Key。
- 当前模型仍存在时保持不变；失效时优先兼容默认文本模型，再选择第一个非明显图像模型，最后回退列表第一项。自动选择只更新草稿，保存后才生效。
- 提示词反推和提示词优化继续共用同一个 `textModelID`；模型列表不持久化，切换配置、API Key 或 BASE_URL 时清空。
- 一键配置 FHL Responses 不再覆盖已有的非空模型选择，固定 `GPT-5.5` 提示文案改为“已配置的 FHL 文本模型”。

## 文本模型验证

- 定向前端测试 `48/48` 通过；完整前端测试 `364/365`，唯一失败仍是既有 Windows PowerShell `Get-FileHash` 环境问题。
