# Windows V2.0.4 反推图像文件选择器崩溃修复

## 问题

在完整 Wails 开发程序中点击“可选：导入反推图像”会调用 Go `runtime.OpenFileDialog`。Windows WebView2 日志显示原生文件对话框返回 `parameter is incorrect`，随后 `Chromium.Focus`/Wails 窗口进程退出，表现为后台崩溃。该问题发生在文件对话框打开阶段，尚未进入图片导入或反推请求。

## 修复

- 反推图像入口改用 WebView 内置的隐藏 `<input type="file">`，限制 PNG/JPEG/WebP。
- 选中文件后继续调用现有 `importReversePromptImageFile`，保留受管导入、预览、工作区隔离和反推请求链路。
- 文件输入每次选择前清空 value，允许重复选择同一文件。
- 仅移除反推图像入口对原生 `OpenImageDialog` 的依赖；普通源图、批量输入和历史导入流程不变。
- Wails 事件注销在 IPC 已关闭（例如 WebView 正在退出）时改为容错处理，避免清理阶段的二次异常掩盖原始关闭原因。

## 验证

- TypeScript 通过。
- Node 回归 `739/739` 通过，新增合同确认反推入口使用 WebView 文件输入且不再绑定 `onSelectReversePromptImage`，并覆盖 IPC 已关闭时的事件清理。
- UI 定向测试通过（FHL 文本配置 `3/3`）。
- Codex 浏览器在完整 Wails 页面 `http://127.0.0.1:34115/` 捕获单文件选择器事件；点击后 Wails EXE 保持运行，Bridge `127.0.0.1:47632/fhl-ps/v1/health` 继续返回 `ok=true`。
- 未上传用户文件，未调用真实或付费生图 API；未读取或修改 Photoshop 插件源码、V2.0.3、Android 或独立 Bridge 契约仓库。

- Wails 日志仍可能在其他原生文件对话框（普通源图/批量输入）触发同类 WebView2 问题，本批未改变这些入口。
