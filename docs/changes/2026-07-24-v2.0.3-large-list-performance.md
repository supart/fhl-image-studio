# V2.0.3 Large-List Performance And Recovery

## Scope

- Virtualize the batch result grid, full history gallery, and batch input queue.
- Use 384px AVIF thumbnails in list views and defer full image access until an original-image action.
- Remove destructive history trimming, recover batch results by ID/path, and coalesce workspace persistence.
- Migrate release/development data into stable namespaces and prepare local V2.0.3 artifacts.

## Implementation

- Added `@tanstack/react-virtual` row virtualization with three-row result/gallery overscan and four-row input overscan.
- Added Vite media registration with path authorization, stable file-stat cache IDs, two-worker `sharp` thumbnail generation, and separate thumb/full URLs.
- Made Wails regenerate missing legacy thumbnails during media registration.
- Upgraded IndexedDB to version 3 with a unique `[createdAt, id]` index, strict 48-item paging, directional cursors, and ID batch reads.
- Persisted history metadata without Blob fields and without full Base64 when a durable output path exists.
- Rebuilt missing successful metadata from persisted task records and treated task `savedPath` as a valid result independently of the loaded history page.
- Raised settled browser group retention to 500 and changed workspace persistence to a 500ms trailing write with terminal/page-hide flush.
- Added stable release/development namespaces, one-time localStorage/IndexedDB/Keyring migration, and legacy namespace coverage in secure API clearing.
- Updated desktop, CLI, Skill, workflow, launcher, packaging, and source-package metadata to V2.0.3. Android metadata was not changed.

## Focused Verification

- `npm run typecheck`
- Batch result recovery, browser registry, namespace, credential clear, virtual-list contract, and independent batch submission tests.
- Wails backend media tests, including AVIF thumbnail registration.

Full release verification is recorded separately in `V2.0.3_ACCEPTANCE_REPORT.md` after package creation.

## Final Release Verification

- Added portable cold-start isolation: portable builds return no legacy
  WebView migration candidates, while installed builds keep their upgrade path.
- Legacy Keyring credentials are considered only when their source namespace
  contains non-credential application state.
- Full verification passed: Node 539/539, UI 12/12, frontend typecheck/lint/
  Windows build, desktop and CLI Go test+vet, Worker 5/5, and diff check.
- The rebuilt packaged E2E fixture mounted 36 of 397 result cards and 8 input
  rows. No full-image or Blob URL was present before an original-image action.
- Reload restored the isolated empty state and browser console errors were 0.
- Portable, ZIP, and source compliance/safety scans all returned 0 issues.
- A disposable normal cold start wrote only its own package-local WebView
  profile; no V2.0.2.1 namespace or user image file appeared.
