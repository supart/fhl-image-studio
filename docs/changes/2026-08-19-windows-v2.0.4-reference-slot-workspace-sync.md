# Windows V2.0.4 参考图删除状态同步修复

## 批次目标

- 修复参考图删除后，添加图片、切换分辨率或切换工作区又恢复旧槽位的问题。
- 在 Windows 参考图右键菜单增加照片属性读取；只有实际读取到的字段才显示。
- 同步统一局部编辑入口文案为“裁切局部重绘”。

## Git 基线与分支

- 开始提交：`2836bde docs(dev): record camera upload normalization`。
- 开发分支：`codex/windows-v2.0.4-feature/reference-slot-workspace-sync`。
- 本批提交：待验证收口后创建，提交信息为 `fix(state): persist reference slot removals per workspace`。
- 回退方式：使用 `git revert`，不使用 `reset --hard`；不设置 upstream，不推送远程。

## 根因

`removeSource()`、`clearSources()` 和 `reorderSources()` 只更新顶层运行态，当前工作区快照仍保留旧 `workspace.sources`。后续添加图片、自动比例同步、分辨率切换和标签恢复读取快照并回写，因此已删除图片重新出现。异步导入还可能在用户删除其他槽位后用旧快照覆盖最新列表。

## 实现结果

- 参考图增删、清空和排序使用捕获的 `activeWorkspaceId`，同时更新顶层运行态和当前工作区快照。
- 添加图片和异步导入改为读取目标工作区的实时参考图列表；迟到结果不能覆盖用户刚删除的其他图片。
- 导入和历史恢复优先使用自然像素 `width/height`，只在缺失时回退到预览尺寸。
- 受管导入图片解析 JPEG EXIF，支持厂商、型号、镜头、时间、ISO、快门、光圈、焦距、方向、软件和原始像素；缺失字段不显示。
- 右键参考图新增“查看照片属性”，不删除原文件、历史或受管媒体。
- 普通图入口、工作台标题和错误提示统一使用“裁切局部重绘”。

## 高分辨率实现

- 源图校验上限与后端受管输入一致为 `100MP`、单边 `16,384px`；裁切区域和编辑结果仍限制为 `64MP`。
- 本地文件导入上限单独提高到 `200MB`，API 请求体仍保持原有 `50MB` 上限；这样大体积相机 JPEG 可以保留在本地编辑，但不会绕过 FHL 上传预处理。
- Windows 桌面端新增 `PasteLocalEdit` 磁盘端操作。源图超过 `64MP` 时，浏览器不读取整图 Base64 或 Canvas，桌面端按自然像素完成裁切范围内的双线性采样、移动、缩放、旋转、羽化、颜色调整和手绘蒙版采样，输出完整尺寸 PNG。
- 大图手动对齐器预览只读取裁切副本；确认贴回仍保留原图完整尺寸，原图文件不覆盖。
- `CropImage` 在 Windows Wails 宿主优先走受管桌面实现，浏览器和 Android 继续使用各自兼容路径。
