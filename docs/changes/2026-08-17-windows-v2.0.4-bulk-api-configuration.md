# Windows V2.0.4 一键配置 10 个 API

## 目标与边界

- 仅升级 Windows V2.0.4 的 FHL Images 十槽配置；Android、存储命名空间、Profile ID、CLI/Bridge 协议和每槽并发上限 5 不变。
- 批量确认只建立 React 内存草稿，不写 Keyring、不测试连接；只有现有“保存并测试 Images 池”按钮可以落盘并发起测试。
- 浏览器验收只使用合成 Key，不点击保存、连接测试、生成、重试、注册链接或其他付费路径。

## 解析与界面

- 新增 `parseBulkAPIKeyLines()`，输入上限 64 KiB；支持 UTF-8 BOM、CRLF/LF/CR、编号、Bearer、赋值语句和含单个 `sk-...` 的说明行。
- 每个非空物理行必须恰好包含一个有效 Key；重复值保留首次位置，无效行、空行、重复数和超过十槽的数量分别统计，最终只取前十个有效唯一 Key。
- Windows 批量弹窗沿用现有 Modal/Fluent UI；粘贴后 textarea 立即保持空值，预览只渲染固定 `sk-************`，原始内容不进入正文、placeholder、ARIA 或日志。
- 支持“读取系统剪贴板”；Wails 优先调用原生 `ClipboardGetText`，Codex 浏览器回退 `navigator.clipboard.readText()`，继续由 `host.ts` 兼容门面导出。
- 单槽输入框收到多行或多个 Key 时自动转入批量弹窗；父弹窗持有子弹窗状态，Esc、关闭和背景点击优先关闭子层。

## 草稿与凭据事务

- 批量确认先清除全部未保存手工草稿，再按顺序预填槽 1-N；N+1 至槽 10 的已保存 Profile 和凭据不变。
- 批量 Key 只保存在组件引用和草稿状态中，password input 的 DOM value 始终为空；关闭子弹窗、关闭父弹窗、刷新和失效的异步剪贴板请求都会清理临时 Key。
- 保存前读取十槽真实凭据并计算覆盖、目标内重复和旧槽迁移；任一读取失败、受影响槽有排队/运行任务或用户取消确认时零写入。
- 目标凭据直接写入 Keyring 并逐槽回读；全部目标一致后才删除旧重复 Profile，删除前再次检查任务状态并验证凭据残留为空。
- 写入或回读失败不会清理旧重复槽；已完成的早期目标允许保留，错误只报告槽号和已完成数量，不包含 Key、尾号或底层异常秘密。
- 保存后仍沿用既有全池测试和活动 Profile 选择规则；本批浏览器验收没有执行该路径。
