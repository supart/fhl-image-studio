# Windows V2.0.4 Runtime Host 能力模块

## 目标与边界

将前端 `runtime/host.ts` 按宿主上下文、任务、文件/对话框、媒体和凭据/上游探测拆分，保留 `host.ts` 作为兼容门面。本批不修改 52 个公共导出、调用方 import、Wails/Android/browser fallback、请求结构、Store 状态、Bridge v1 或用户存储。

## 实现

- `hostContext.ts` 统一宿主识别、能力矩阵、内核运行模式、事件、主题、本地预览和 E2E bootstrap；共享 `unsupportedMessage` 不再迫使其他领域依赖任务模块。
- `hostTasks.ts` 持有生成、编辑、提示词优化/反推、取消、远程任务 controller 和 Android job 路由；远程结果保存单向依赖媒体能力。
- `hostFiles.ts` 持有单图/多图/批量目录选择、历史文件、输出目录选择、外部 URL/文件打开、文本读取和 E2E 浏览器持久化回退。
- `hostMedia.ts` 持有图片保存/分享/导入/登记/读取/变换、素材目录同步及浏览器输入图持久化。
- `hostCredentials.ts` 持有浏览器/Wails/Android 凭据、输出目录配置和 Responses/APIMart/RunningHub 上游探测。
- `host.ts` 缩为 62 行显式重导出；现有生产调用方和测试 mock 不需要改 import。
- 将批量文件名控制字符清理改为字符码过滤，移除拆分路径继承的一条 Lint warning，总数由 59 降为 58。

## 架构门禁与审计

- 新增 TypeScript AST 测试，精确锁定 52 个门面导出、禁止能力模块反向导入 `host.ts`、要求门面只含重导出，并将六条能力模块依赖边锁定为无环基线。
- 原本直接检查 `host.ts` 内部字符串的 APIMart、批量目录、E2E bootstrap 和易失图片测试改为检查实际所有者模块；现有 `runtimeHost.test.mjs` 行为回归保持不变。
- 专业 agent 只读审计确认依赖方向为 `Tasks -> Media -> Context`、`Files -> Credentials/Media -> Context`；同时发现 browser 远程任务没有统一 `settled` 事件。后者属于任务/Bridge 行为合同，登记到后续加固批次，本批不混入行为变更。
