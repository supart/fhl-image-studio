# Windows V2.0.4 FHL 文本 API 动态模型列表

## 范围

独立 `FHL 文本 API` 配置区复用现有 `GET /v1/models` 探测，允许用户手动获取当前文本 Key 可见的模型并选择用于提示词优化、图片反推和 Photoshop Bridge Prompt Profile 的模型。普通 Profile、FHL Images 池、APIMart、RunningHub、Bridge v1、Android 和 V2.0.3 均未修改。

## 实现

- Go/Wails `ProbeUpstreamResult` 在保留 `modelCount` 的同时返回 `models`。
- 模型 ID 按上游顺序去重，并过滤空值、超过 128 个 Unicode 字符、控制字符；响应超过 1 MiB 时明确拒绝。
- 浏览器开发回退与 Wails 使用相同的模型清洗规则；旧后端缺少 `models` 时兼容为空数组。
- “获取模型”优先使用输入框的新 Key，但不会保存；输入框为空时读取现有安全凭据。无 Key、格式错误、超时、非 2xx、无效 JSON 和空模型列表均显示明确错误。
- 获取后的列表只存在当前配置会话，不写入本地设置。刷新失败不清空当前选择，已保存模型未被上游返回时仍保留并标注。
- `gpt-5.6-sol`、`gpt-5.5` 和自定义模型入口继续可用；选择模型仍复用现有 `fhlTextAPIModelID` 持久化和请求链路。
- 模型出现在 `/v1/models` 只代表 Key 可见该 ID；用户仍需点击“保存并测试文本 API”确认其支持 `/v1/responses`，软件不会静默降级。
