## 根因

此前普通图局部编辑在 Codex 浏览器中能够打开裁切和对齐界面，但 `PasteLocalEdit` 只有 Wails 原生实现。浏览器没有该宿主绑定时，流程直接失败；高分辨率路径也可能退回整图读取，造成不必要的 Base64/Canvas 内存峰值。

## 实现结果

### 路径受限的浏览器宿主接口

- 新增 `POST /__image-studio-files/crop-image`：只接收受管图片路径和自然像素 `x/y/width/height`，使用 Sharp 在本地裁切；原图不修改。
- 新增 `POST /__image-studio-files/paste-local-edit`：只接收受管源图、编辑图路径和对齐参数，输出到项目 `input`，不传输图片 Base64。
- 两条接口统一执行项目路径包含校验；越界、非整数、无法读取尺寸和临时输出失败都会在本地返回错误并清理临时文件。
- Wails `CropImage` / `PasteLocalEdit` 仍优先；只有本地浏览器预览且没有原生方法时才使用 Vite/Sharp 通道，其他平台回退行为不变。

### 高清平面贴回

- 先读取源图、编辑图和蒙版 metadata，再执行尺寸、裁切边界和工作内存预检。
- 原图上限 `100MP / 16,384px`；编辑图和蒙版上限 `64MP / 16,384px`；工作内存估算上限约 `768MiB`。
- 贴回只在 `cropRect` 自然像素范围内采样；编辑图为 `1K`、`2K` 或任意比例时，都不会扩大物理覆盖范围。
- 源图只抽取裁切区域并原地合成，输出用随机临时文件写入，尺寸确认后原子改名；源文件和失败半成品均不覆盖、不保留。
- 继续复用现有双线性采样、移动/缩放/旋转、亮度/对比度/色相、蒙版和羽化规则。

## Codex 浏览器真实验收

使用本机合成的非透明 JPEG/PNG 夹具，不调用真实或付费生图 API。

1. 原图 `7876×10835`（约 85MP）导入“裁切局部重绘”，工作台显示自然像素尺寸。
2. 比例从 `4:3` 切换到 `3:4`，拖动镜头框后保存，生成 `2659×3545` 局部裁切副本。
3. 选择 `2048×2048` 编辑图打开对齐器，点击“确认贴回”成功关闭弹窗并生成“局部贴回”终态。
4. 输出仍为 `7876×10835`；像素差异边界为 `x=3656,y=3999,width=2652,height=3535`，没有整图覆盖。
5. 源文件 SHA-256 为 `5A2F0AC289B443B385C5714740E2B81901DC2ECD1896253535A1B4D16843FED5`，贴回前后不变。
6. `1252×930`、`1440×900`、`1024×768` 均无横向溢出，弹窗动作区可见；最终浏览器控制台新增 warning/error 为 `0`。
7. 重启后在最新 `http://127.0.0.1:5173/` 页面复查版本为 `V2.0.4`，用户原有工作区和历史保持可见；本轮合成历史和参考图已从隔离页面清理。

## 大图门禁证据

- `100MP` 源图在完整解码前被拒绝，返回“贴回所需工作内存过大（估算 `915MiB`，上限 `768MiB`）”，没有输出文件。
- `85MP` 源图配合法定 `8000×8000` 蒙版在解码蒙版前被拒绝，返回“贴回所需工作内存过大（估算 `804MiB`，上限 `768MiB`）”。
- 超过门禁时不会创建历史半成品，也不会退回浏览器整图 Base64 路径；提示用户缩小裁切区域后重试。
