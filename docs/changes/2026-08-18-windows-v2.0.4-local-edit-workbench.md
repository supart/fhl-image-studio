# Windows V2.0.4 统一局部编辑工作台

## 批次目标

把普通图局部编辑入口升级为与 360 工作台一致的双栏弹窗。普通图在选区后先进入轻量草稿，用户确认裁切后才创建历史；提示词、比例、输出尺寸、导入和生成入口都留在工作台内。360 全景继续交给现有球面查看器和贴回链路。

## 修改范围

- Windows V2.0.4 前端类型、工作区持久化和 Store 工作台动作。
- 新增 `LocalEditWorkspaceModal` 及响应式双栏样式，支持普通图/360 全景模式切换。
- 普通图选区草稿按原图自然像素保存，确认后复用现有裁切、受管媒体和 `LocalEditRoundtripRef` 历史链路。
- 工作台内增加比例、输出尺寸、质量、提示词、风格、单任务生成和 PNG/JPEG/WebP 导入入口；对齐仍复用现有平面/全景对齐器。
- 未修改 Android、V2.0.3、正式附件、正式标签、API/Profile 或真实请求协议。

## 实现结果

- 新增 `LocalEditWorkbenchDraft`，只保存 source history ID、路径、自然尺寸、裁切矩形和文本参数，不把大图 Base64 放进 Zustand 或工作区存储。
- `startLocalEditRoundtrip` 现在只打开工作台；“确认裁切并编辑”才调用 `commitLocalEditWorkbenchCrop` 创建局部裁切副本，取消直接清理草稿且不增加历史。
- 工作区切换、刷新恢复和退出 flush 会保留草稿；草稿更新、模式切换和取消均通过当前 workspace 持久化边界处理。
- 普通图工作台提供拖动/四角缩放裁切框、比例预设、输出尺寸、质量、独立提示词和风格按钮；没有 2:1 的源图切换到全景模式时会明确阻止全景生成。
- 生成调用现有 `submit()`，批次强制为单任务；外部 PNG/JPEG/WebP 继续进入受管媒体和现有手动对齐器，原图和中间历史保留。
- 360 模式保留现有 PanoramaViewerModal 球面渲染和全景贴回算法，普通图的整图蒙版入口不受影响。

## 风险与限制

- 本批浏览器验收没有点击“确认裁切并编辑”、生成或外部导入，以避免修改用户现有历史和触发真实上游；这些路径沿用已通过的 CropImage、Store submit 和现有平面贴回核心，需在离线夹具工作区做下一轮专门验收。
- 对齐、蒙版、羽化和色彩控制仍由 `PanoramaPastebackAlignModal` 提供；工作台负责统一入口和阶段状态，不重写既有平面/球面采样算法。
- 当前 360 模式从工作台转入现有全景查看器，保持历史兼容和球面算法稳定。
