# Windows V2.0.4 精确 CI 与版本漂移门禁

## 目标与边界

收窄桌面端 CI 的 Go test/vet 范围，并确保所有前端生产构建、Portable、源码暂存、CI 和 Windows Release 在产生构建或发布副作用前拒绝版本漂移。本批不修改产品功能、Bridge、CLI 命令、请求结构或存储，不执行 Portable/源码打包，不生成 EXE/ZIP，不推送或发布。

## 专业审计

- 桌面 CI 原来的 `go vet ./...` 与 `go test ./...` 会额外解析 `image-studio/frontend/node_modules/flatted/golang/pkg/flatted`，把前端依赖内的 Go 源码误当成桌面模块。
- 桌面端真实包范围只有主包 `.` 和 `./backend`；CLI 的 `./...` 仍只覆盖 CLI 自身四个包，race job 的 `./backend` 也已精确，两者保持不变。
- Portable、源码准备、Release identity 和 Wails Windows job 已有版本检查；真正缺口是所有 `npm run build*` 共用的 `platform-vite.mjs` build 分支，以及只做合规扫描的 Release hygiene job。

## 实现

- `platform-vite.mjs` 在任何 TypeScript 编译和 Vite 资产输出前运行 `sync-version-metadata.mjs --check`，一处覆盖 `npm run build`、五个 `build:*`、Wails `frontend:build` 和 CI 构建矩阵。
- CI 桌面命令改为 `go vet . ./backend` 与 `go test . ./backend`；`docs/build.md` 的手工验证命令同步收窄。
- Release hygiene 增加固定 Node 版本和显式版本漂移检查，随后才运行源码合规扫描。
- Portable、源码暂存和 Release 工作流保留现有实现，仅用离线顺序合同锁定检查早于创建输出目录、构建、复制、压缩、上传和发布。

## 离线合同与自动化

- 新增真实临时构建夹具，成功路径严格记录 `version -> tsc -> vite`；版本检查返回失败时，断言 TypeScript 和 Vite 均未启动。
- 新增 CI job 范围、Release hygiene、Portable、源码准备和 Release 发布顺序合同；定向门禁测试 `7/7` 通过。
- 版本漂移、TypeScript、Node `600/600`、UI `64/64`、Windows 前端 1,968 modules 构建通过；Lint 为 `0` errors、`58` warnings，与批次 12 基线一致，本批触及前端源码零 warning。
- 桌面端精确 `go vet . ./backend`、`go test . ./backend` 通过且 `go list . ./backend` 只返回两个目标；CLI `go vet ./...`、`go test ./...` 通过；Worker `5/5`、gofmt 和 `git diff --check` 通过。
- 首次把开发工作树直接交给发布合规脚本时按设计命中 `node_modules`、`dist` 和浏览器审计日志 20 项；加入本批记录后，Git 已跟踪及待提交的最终 684 文件源码快照为 `0` 项，快照已移入回收站。
- UI 第一次与四组前端检查并行运行时，`SettingsPanelGate` 的 effect 计数出现一次时序失败；单测立即复跑及整套 UI 串行复跑均通过，本批没有修改该组件或放宽断言。
