# Windows V2.0.4 Photoshop Bridge 远程任务终态加固

## 目标与边界

修复 APIMart、RunningHub 经桌面前端执行的 Photoshop Bridge 任务在前端失联时永久停留于运行中，以及重复完成可能重复写结果文件的竞态。保持 Bridge v1 HTTP 路径、Wails 方法、公开状态、CLI、请求 schema v2、序列化和存储兼容；本批不调用真实 API，不改 CI/发布链，不生成发布附件。

## 专业审计结论

- 远程 dispatch 原先只发 `ps-bridge:remote-job`，没有后端 watchdog；页面重载、事件丢失或 Promise 永不返回会永久占用 Bridge 的单任务槽。
- `CompleteRemote` 原先先复制活动任务，再在锁外保存图片；并发完成可同时写图片、缩略图并登记媒体，末端状态检查只能阻止第二条历史，不能阻止磁盘副作用。
- `CompleteRemote`、`FailRemote` 和 `UpdateRemote` 对已终态任务返回错误，无法安全接收传输重试或 watchdog 后的迟到回调。
- 浏览器远程生成只发 `result/error`，没有 `settled`；原生任务事件注册表依赖 `settled` 释放监听器、任务元数据和连续池容量。

## 实现

- 为 desktop executor 的 APIMart/RunningHub 任务增加内部终态 claim；成功、失败、取消和 watchdog 按第一个 claim 获胜，其他重复或迟到回调幂等返回，不新增 Bridge v1 可见状态或字段。
- 完成回调在任何保存副作用前原子 claim，确保只有一个调用方能保存图片、生成缩略图、登记媒体和写入历史。
- 增加 2 小时后端 watchdog。该上限明显高于现有 provider 单次轮询和重试预算；超时后任务统一进入 `failed`，写入非敏感错误，清理临时输入，发一次 `ps-bridge:remote-cancel` 并释放后续 Photoshop 任务。
- 正常完成、失败、取消、清空 Profile 和 Bridge 停止都会停止 watchdog；定时器回调即使已进入调度，也会被终态 claim 拒绝，不能产生第二终态。
- 已完成或正在 finalizing 的合法远程任务接受重复 Complete/Fail/Update 并保持原终态；未知任务或非远程 executor 仍返回原有 `not active` 错误。
- 浏览器远程任务在 `finally` 中删除 controller 后无条件发一次 `settled:${jobId}`；成功顺序为 `result -> settled`，失败为 `error -> settled`，取消只发 `settled`。
