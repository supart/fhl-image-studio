# Windows V2.0.4 任务动作模块化

## 目标与边界

把任务选择、单项取消、批量取消排队项、清理失败项、队列插队和兼容取消入口迁出主 Store，同时保持 `useStudioStore` 公共接口、任务记录、workspace session v1、Wails 事件名、连续池容量语义和 Bridge v1 不变。本批不迁移连续池控制器、浏览器任务生命周期、原生任务事件编排、`host.ts` 或 Bridge。

## 缺陷与实现

- 先用 `createWorkspaceActions` 行为测试复现关闭工作区只解绑 `progress/log/preview/result/error`、漏掉 `settled:${jobId}`；修复为六类事件统一解绑，防止关闭后的迟到终态继续触发旧工作区逻辑。
- 新增 `studioStore.tasks.ts`，通过显式运行时依赖注入宿主取消、自动重试计时器、连续池启动集合、队列启动/pump、FHL 容量保留和自动比例同步。
- 将纯函数 `taskRuntimePatchForWorkspace()` 从主 Store 迁入任务模块，主 Store 和新动作共用同一派生逻辑，没有复制实现。
- `studioStore.ts` 继续提供原动作签名，只做兼容转发；`selectBatchTaskForCancel()` 和 `cancelSelectedTask()` 仍经 Store 公共入口委托，保留现有替换与测试语义。
- 取消继续先提交 `cancelled` 终态，再调用宿主；第二次读取任务状态，避免并发完成的任务被旧取消快照覆盖。
- 原先依赖 `studioStore.ts` 内部函数位置、变量名和源码顺序的取消/清理/插队字符串断言，改为模块行为测试；组件接线和公共类型断言继续保留。

## 行为覆盖

- 9 条任务动作测试覆盖：有效编辑任务来源恢复、未知选择隔离、取消先落终态、普通任务 meta 删除、FHL 连续池容量保留、取消期间并发终态保护、仅取消活动工作区 queued 项、清理 failed/interrupted/终图缺失项、插队资格与防重、两个兼容委托入口。
- 工作区领域测试新增 `settled` 解绑回归，并验证取消请求、工作区删除和 `runningJobMeta` 清理。
- 所有测试只使用内存状态和 spy，不调用真实宿主、API、文件选择或生成路径。
