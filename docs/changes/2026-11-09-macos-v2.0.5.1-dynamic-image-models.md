# macOS V2.0.5.1 动态生图模型选择

## 范围

- 基线：macOS V2.0.5 发布提交 `6c1da24bba49dd312fc21dc79981de6e4aed18e0`
- 目标：macOS V2.0.5.1
- 本轮只增加桌面端 FHL Images 模型兼容性和背景模式边界，不把用户 API、Keychain、图片、历史或日志带入发布资产；本机配置清理由应用的 API 凭据库操作完成。
- 不修改 Android、Windows 发布分支、Photoshop 插件和独立 Bridge 协议。

## 行为变化

- 删除前端和 CLI 对 FHL 生图模型的固定 ID 白名单。
- `/v1/models` 返回的所有非空模型 ID 都可以进入下拉框并保存；这允许上游先发布 `gpt-image-2.6` 或其他未来模型，而客户端无需再次发版才能选择。
- 通过 `^gpt-image-2(?:$|[.-])` 动态识别 GPT Image 2 系列。该系列使用亮色高亮，其他模型使用灰色说明，但所有选项保持可点击。
- 背景选择永久显示：精确 `gpt-image-2`、`gpt-image-20` 和其他未知模型禁用透明；所有带点号或连字符后缀的 `gpt-image-2.x` / `gpt-image-2-*` 模型（包括 2.5、2.6 及未来 2.x）支持透明 PNG。

## 兼容与安全

- 空模型 ID 仍阻止 FHL 生图，避免把未完成配置当作有效模型发送。
- 选中的模型继续同步到全部 FHL Images 槽和 CLI 配置。
- 模型列表、API Key 和用户数据不进入发布包；测试使用离线 Mock 和本地 fixture。

## 验证计划

- 前端模型下拉 UI：2.x 模型高亮、灰色模型可选、新 `gpt-image-2.6-sunburst` 可保存。
- 前端 store：未知未来模型可选，空模型仍拒绝，不支持透明的模型切换时恢复 `opaque`，2.6 和未来 2.x 模型可保留透明状态。
- CLI client：未来模型和灰色模型不因客户端白名单被拒绝。
- 版本同步、TypeScript、UI、Go test/vet、macOS Universal 构建和 bundle verifier 按发布前门禁执行。
