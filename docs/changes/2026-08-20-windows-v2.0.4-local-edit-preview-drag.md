## 问题与根因

普通图工作台的“镜头预览”原先固定在左侧画布右上角，展开后会遮挡原图，用户无法把它移到不影响取景的位置。预览节点也没有自己的坐标约束。

实现拖动后，首次浏览器验收在展开预览时暴露了一个布局回归：舞台 `ResizeObserver` 每次回调都创建新的 `frameSize` 对象，即使宽高没有变化也触发 React 更新；与预览布局观察叠加后触发 `Maximum update depth exceeded`。该问题已通过按宽高值比较后才更新状态修复。

## 实现结果

- `LocalEditPreviewPosition` 和 `clampLocalEditPreviewPosition()` 负责将浮窗 `left/top` 限制在 `.lew-stage` 内，并保留安全内边距；舞台小于预览时安全钉在原点。
- 预览标题栏使用 Pointer Events、`setPointerCapture`、释放/取消/丢失捕获处理，拖动只保存在 modal 本地 React state，不写入 Zustand、workspace、history 或 Base64。
- 标题栏增加抓取光标、触控拖动禁用、焦点样式和无障碍标签；展开/收起按钮不会启动标题栏拖动。
- 舞台尺寸变化和窗口 `resize` 会重新约束已定位的预览；预览位置变化不会重复注册观察器。
- 舞台 `frameSize` 观察回调改为值相等时复用旧对象，避免 ResizeObserver 更新循环。
- 新增纯函数边界测试和 UI 合同测试，覆盖越界、异常尺寸、超大预览、Pointer Capture 与 CSS 交互契约。

### 失败与修复闭环

1. 初次展开预览触发 React 最大更新深度错误，工作台被错误边界卸载。
2. 定位到 `ResizeObserver -> setFrameSize` 无条件创建新对象。
3. 按值比较 `frameSize`，并让预览位置观察回调仅在坐标变化时写入；重载后展开、收起和三档视口均通过。
