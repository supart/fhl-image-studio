# V2.0.5 Android 单次图生图占位修复

日期：2026-11-08

## 根因

Android 画布的单任务运行占位同时要求 `!currentImage`。图生图提交必须保留参考图或上一张画布图作为请求快照，因此这个条件在真实图生图场景中为假，等待层不会出现。

## 修复

`AndroidCanvasStage.tsx` 现在只在运行中、可见批次为单槽、结果网格未打开且没有流式预览时显示 `AndroidSinglePendingPreview`。旧参考图和 `currentImage` 仍保留给源图、蒙版和提交逻辑；占位层通过现有绝对定位覆盖旧图。收到流式预览后，预览层取代等待层；任务完成后由最终结果接管画布。

## 验证范围

- 静态聚焦测试覆盖保留 `currentImage` 仍显示占位，以及流式预览出现后占位消失。
- 长构建和 2K 模拟器真实图生图回归在后续批次执行；本记录不把未执行的设备验证写成通过。

## 后续验证结果

- 在 `codex_api36`（API 36，`1440x3200 @ 560 dpi`）真实 Images 图生图中，更换参考图后观察到 `本批预览 · 0/1 · 等待第 1 张预览`，随后流式/最终结果替换占位；通知、历史和当前画布均恢复。
- 前端全量测试 `421/421`、TypeScript、`build:android`、Android JVM `64/64` 和 `assembleDebug` 通过。对应 Debug APK SHA-256 为 `3D6AEBEAF689DE804FE9E0E44042FF378832B5D642EA26BEE0D0ABE9E424C4E8`。
