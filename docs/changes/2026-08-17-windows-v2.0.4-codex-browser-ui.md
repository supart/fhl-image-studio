# Windows V2.0.4 Codex 浏览器开发入口

## 目标

恢复此前 Windows 桌面开发中使用 Codex 内置浏览器直接查看和测试 React UI 的工作方式，同时保留现有 Wails 原生窗口入口。所有改动、依赖和运行进程均限制在 `V2.0.4-开发版` 内，不修改 V2.0.3 或其他项目。

## 实现

- 新增外层 `一键启动V2.0.4-Codex浏览器UI.cmd`，从当前 V2.0.4 源码启动 `npm run dev:windows`。
- 浏览器入口显式使用 Windows 前端目标、`127.0.0.1`、端口 `5173` 和开发存储命名空间 `fhl-image-studio-desktop-dev`。
- `platform-vite.mjs` 新增可选环境变量 `IMAGE_STUDIO_DEV_PORT`；设置后向 Vite 传递 `--port` 与 `--strictPort`，避免端口占用时静默切换到 5174，导致 Codex 打开错误页面。
- 外层开发说明区分两个入口：Codex 浏览器适合日常 UI 开发与交互检查，Wails 窗口用于系统文件选择、系统凭据、Photoshop Bridge 等原生能力复核。
- 原有 `一键启动V2.0.4开发版.cmd` 保持不变。

本批没有修改产品功能、API、数据结构、版本号、稳定存储命名空间或迁移标记，因此没有向 `CHANGELOG.md` 添加用户可见条目。

## 启动问题与修复

新 `.cmd` 首次以 UTF-8 LF 行尾运行时，Windows `cmd.exe` 在中文路径和括号块中错误拆分了命令，启动在读取 `package.json` 前失败。未启动服务，也未写入应用数据。

启动器随后转换为 Windows CRLF 行尾，再次运行成功。Vite 报告 `windows` 模式并固定监听：

```text
http://127.0.0.1:5173/
```

## 恢复点

日常开发先双击外层 `一键启动V2.0.4-Codex浏览器UI.cmd`，保持命令窗口运行，再在 Codex 内置浏览器打开 `http://127.0.0.1:5173/`。若 5173 已被占用，启动器会失败并保留明确错误，不会自动换端口。
