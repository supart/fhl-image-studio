## Clean-State And Safety Verification

- Source compliance scan: 0 issues.
- Portable folder and ZIP release-safety scan: 0 issues.
- No `cli.env.local`, `fhl-api.local.json`, `browser-jobs.v1.json`, WebView profile, API credential, generated output, or user history was packaged.
- The Portable ZIP is the clean distribution artifact. Its first launch creates its own package-local `config/webview` runtime data; a locally launched extracted folder is therefore no longer a clean artifact for redistribution.
- API credentials are never stored in the ZIP. On the same Windows account, a Portable may recognize existing `FHL Studio` entries from Windows Credential Manager so an upgrade can retain the user's prior configuration. A new Windows account or computer has no such entries and starts without configured credentials.
- Source private-path scan found no username, development-drive path, `.prerelease-build`, port 5174, clipboard-temporary path, or AppData temporary path.
- No Photoshop CCX, ZXP, plugin ZIP, plugin EXE, plugin source, or sales delivery was included.

- Validation-only `node_modules` and `frontend/dist` were removed before the final source archive was created.

## Formal Defaults

- The shipped archive contains no API Profile metadata or current API selection. On a Windows account that already has compatible FHL Studio credentials, the runtime may display those existing system credentials after its own first launch; this does not place a credential in the package.
- No generation task, history item, input image, output image, or thumbnail is present.
- Initial generation mode is text-to-image with one image, continuous mode off, 1:1, 2K, standard quality, and PNG output.
- Bridge can start without credentials and reports that the current Profile is not ready; no provider request is made.
